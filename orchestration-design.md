## Goal
Build the full 17-module app from `spec/keirasjourney-spec.md` to a live site with a
fleet of autonomous agents. Grahem is hands-off except at three irreversible gates.
The supervisor (Claude, this role) monitors, reviews, and merges; agents do the work.

## Decisions locked this session
- **Runtime:** 8 local git worktrees = 8 parallel Claude agents on this machine, each an
  isolated checkout on its own branch. GitHub Actions does CI + merge→deploy only (it does
  NOT host the agents).
- **AWS autonomy:** infra agent writes all IaC (CDK). One human gate before the first real
  apply + domain confirmation. Everything after is autonomous. Never touch account 791321067225.
- **Merge/deploy:** supervisor auto-merges PRs that pass spec-review + CI. Merge to `dev`
  auto-deploys to a staging S3/CloudFront. Prod promotion to the real domain = Grahem's one tap.
- **Sequencing:** infra → prove ONE vertical slice (auth + Activity Journal, deployed, Grahem
  tests it) → then fan out all remaining modules across the 8 worktrees.
- **Git rule:** branch off `dev`, PR into `dev`, never auto-merge to `main`. `main` = prod,
  promoted only by Grahem.

## Repo layout (monorepo)
```
/infra            CDK (TypeScript) — all AWS
/backend          Lambda (TypeScript); modules/<module>/ per module; shared data-access lib
/frontend         React + Vite + TS; src/modules/<module>/ per module
/specs            one spec file per module + foundational specs (split from the master spec)
/.agent-bus       coordination state (the "message bus") — board, heartbeats, checkpoints
/.github/workflows ci.yml, deploy-staging.yml, deploy-prod.yml
/docs             CLAUDE.md, this design, master spec
```

## Agents
- **Infrastructure agent (runs first, 1 worktree):** CDK for Cognito (username-only, 3 users),
  DynamoDB single table + GSIs, API Gateway HTTP API + JWT authorizer, Lambda, SQS + DLQ for
  hydration, S3 + CloudFront (staging + prod, OAC, not public), Route53 + ACM (gated), SSM
  params, least-privilege IAM, and the GitHub OIDC deploy role. Synthesizes a plan, STOPS at
  the apply gate, then applies and writes stack outputs to SSM.
- **Worker agents (8 worktrees, waves):** each owns ONE module spec. Implements backend
  handlers + frontend + tests, runs hands-off engineering review (plan-eng-review + code-review
  skills) before opening its PR. Branches off `dev`, PRs into `dev`. Strict file-ownership
  boundaries (below) so parallel workers never edit the same file.
- **Spec-reviewer agent (loop, own worktree):** on a schedule, reads each worker's checkpoint +
  open PR, runs the spec-review / qa-review skills, posts findings as PR comments and to
  `.agent-bus`, and gates PRs for spec conformance. Communicates with workers through the bus.
- **Supervisor (Claude):** watches `.agent-bus` + the PR queue, merges PRs that are
  reviewer-approved and CI-green (→ staging deploy), arbitrates conflicts and stalls, and
  escalates to Grahem only at the three gates.

## Message bus / state (`.agent-bus/`)
- `board.json` — task board: each module's owner worktree, status (todo/in-progress/review/
  merged/blocked), branch, PR number, dependencies.
- `agents/<agent>.json` — heartbeat: last-updated timestamp, current task, status, blockers.
- `checkpoints/<module>.md` — the worker↔reviewer conversation thread for that module.
- All updates land via commits/PRs so state changes are atomic and auditable. (GitHub Issues
  were considered; flat files chosen for atomic coupling to the diffs they describe.)

## Work-slicing — collision avoidance
The single-table + monorepo design is collision-prone, so:
1. **Foundational phase builds shared contracts first and freezes them:** the single-table
   data-access library, the API route registry, the auth middleware, and the design tokens.
2. **Each module worker touches only its own paths:** `backend/modules/<m>/`,
   `frontend/src/modules/<m>/`, `specs/<m>.md`, and registers its routes + nav via an
   **append-only manifest** (one file per module — no shared-file edits), so parallel PRs
   never conflict.
3. 8 worktrees = 8 lanes; 17 modules flow through in waves, ordered by the reviewer/supervisor
   per the dependency graph (data + auth + shared libs before feature modules).

## Build sequence + gates
0. **Repo init:** create `dev`, scaffold the three apps, CI, CODEOWNERS, branch protection.
1. **Infra:** CDK synth → **GATE 1: Grahem approves the plan + confirms the domain** → apply.
2. **Vertical slice:** auth + data-access lib + API router + Activity Journal, deployed to
   staging → **GATE 2: Grahem tests the slice end-to-end.**
3. **Fan-out:** 8 workers build the remaining 16 modules in waves; reviewer loop runs;
   supervisor merges green+approved PRs; staging updates continuously.
4. **Integration:** dashboard + master timeline aggregation, cross-module wiring, full QA.
5. **Prod:** **GATE 3: Grahem taps promote** → deploy to the live domain → final test.

## CI/CD (GitHub Actions)
- `ci.yml` on PR: typecheck, lint, unit tests, `cdk synth` (no deploy).
- `deploy-staging.yml` on merge to `dev`: build frontend → `s3 sync` staging bucket →
  CloudFront invalidate; `cdk deploy` staging backend.
- `deploy-prod.yml` on merge to `main` (manual promotion): same against the prod stack.
- **AWS auth from CI:** GitHub OIDC → scoped IAM role in the wnu account. No long-lived keys
  in CI. (Local agents/infra use the `wnu` profile already scoped to this folder.)

## Guardrails
- Budget alarm on the wnu account; all infra in us-east-2; least-privilege IAM; S3 private
  behind CloudFront OAC; Cognito email-less per spec.
- Heartbeat timeout → supervisor flags a stalled worktree; per-task max retries then escalate;
  Bedrock calls rate-limited; zero secrets in the repo (SSM / Secrets Manager + Actions secrets).
- Branch protection on `dev` and `main`; `main` requires Grahem's approval.

## Approaches considered
- **Minimal:** one worktree, sequential modules. Safe but slow; ignores the 8-worktree ask. Rejected.
- **Chosen:** 8 worktrees + Actions CI/deploy + gated infra + slice-first. Parallel, de-risked,
  honors every constraint.
- **Lateral:** agents fully hosted in GitHub Actions (survives laptop-off) — conflicts with the
  8-worktree instruction and is harder to supervise live. Rejected per your choice.
